# 利用者向けガイド

このリポジトリは、長期 AHC の **With AI 部門** で解答コードと実験を管理するための作業用の雛形です。Human Only 部門での使用は想定していません。大会の解法、公式ツール、入力データ、完成済みのビルド設定は含みません。

## 1. 大会用の作業場所を作る

このリポジトリを大会ごとに別のフォルダへ複製します。テンプレートそのものに大会固有の解法や実験結果を混ぜないようにします。`src/bin/` に解答コード、`cases/` に入力を置く想定です。問題文や公式ツールは参加者がブラウザで手動取得し、問題文 PDF は `local/problem.pdf`、公式ツールは `tools/` に置きます。共通スクリプトは `scripts/` にあります。`local/` と `tools/` は Git の管理対象から除外されています。取得元 URL と取得日を別途記録し、各配布物の公開条件を確認してください。

Python 3 が比較・スコアボードに必要です。実験一覧の表示は PowerShell スクリプトです。Rust は、この雛形を Rust 解答コードと Rust 製公式ツールで使う場合に必要です。これらのインストール方法やバージョンは大会・利用環境に合わせて確認してください。

## 2. 部門とルールを確認する

大会ページの「部門」タブで With AI 部門を選びます。部門未選択では提出できません。開催時に[長期 AHC の公式ルール](https://info.atcoder.jp/entry/long-ahc-llm-rules-ja)と大会固有の条件を確認してください。`AGENTS.md` は With AI 部門用の作業指示であり、公式ルール全文の転載ではありません。Claude Code をリポジトリのルートで起動すると、`CLAUDE.md` が `@AGENTS.md` を読み込みます。`/context` で読み込みを確認してください。

With AI 部門では解法の考案、実装、実験、結果に基づく改善を AI に依頼できます。ただし、他者が開発に関わった非公開モデル・ハーネスの利用禁止と、通常の AHC における他の参加者との相談・コード共有の禁止などは残ります。独立した AI セッションでも、大会で適用されるルールを確認してください。

## 3. 大会固有の設定をする

`config.example.json` を `config.json` にコピーし、次を設定します。`config.json` は Git 管理から除外されています。

| キー | 設定内容 |
|---|---|
| `input_glob` | 比較する入力ファイルのパターン。例: `cases/dev/*.txt` |
| `time_limit_seconds` | ソルバー1回あたりの制限時間 |
| `scorer_time_limit_seconds` | 採点コマンドの制限時間 |
| `score_direction` | 小さいほど良ければ `lower`、大きいほど良ければ `higher` |
| `score_pattern` | 採点コマンドの出力から点数を抜き出す正規表現。最初の括弧が数値 |
| `solvers` | 版 ID と、その実行コマンドの対応 |
| `scorer` | 公式採点コマンド。`{input}` と `{output}` がファイルパスに置換される |

コマンドは文字列の配列で指定します。ソルバーは入力を標準入力から受け、標準出力へ解答を書きます。相対パスはリポジトリのルートから解決されます（実行ファイルのパスは `/` 区切りでも `\\` 区切りでも構いません）。Windows の実行ファイルには `.exe` を付けてください。採点結果の表示形式は大会ごとに異なるため、`score_pattern` は公式ツールの実際の出力で確認します。

公式 generator・tester・visualizer の配置、ソルバーのビルド、入力生成はこの雛形では自動化していません。`tools/` に置いた公式ツールを使うコマンドは大会ごとに用意します。

## 4. 実験を計画・実行する

1. 比較対象、ケース集合、seed、反復回数、時間制限、スコアの向き、採用基準を決めます。AI に提案・決定を依頼しても構いません。提案者と判断者を `docs/decisions.md` に記録します。
2. `docs/experiments/TEMPLATE.md` を `EXP-001-内容.md` のように複製し、**実行前**に条件を記入します。解法版は `docs/solutions.md` に記録します。
3. ケースの入力を `cases/dev/` などへ置き、`config.json` の `input_glob` を固定します。
4. ソルバーと公式採点ツールを準備してから、比較を実行します。

```text
python scripts/compare_solvers.py EXP-001 baseline candidate
```

結果は `reports/experiments/EXP-001/cases.csv` と `summary.json` に保存されます。同じ実験 ID のディレクトリがあると上書きを拒否します。途中で失敗した場合、完了済みケースを `cases.partial.csv` に残す場合があります。実験記録では、保存された事実と AI の解釈・改善案を分けて記入します。

この比較ツールは、指定した入力集合を各ソルバーで**1回ずつ**実行します。反復回数や seed を含む実験を行うときは、コマンド・入力集合を別途用意し、その条件と結果を記録してください。このツール自体に自動反復や候補探索の機能はありません。

## 5. 保存済み結果を見る

```text
python scripts/show_scoreboard.py --direction lower
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/show_experiment_results.ps1
```

スコアボードの `--direction` は実験時の向きと合わせます。同一ソルバー・ケースに複数の成功結果があれば最良値を使い、全ケースの結果がそろった版だけを表示します。これは記録済みスコアの機械的な相対表示です。採用・棄却の理由は別途記録します。実験一覧は `docs/experiments/EXP-*.md` を読み、`reports/experiment_results.csv` を更新します。

## 6. 公開と記録

テンプレートの Git 履歴は、設計や変更の経緯を追うためのものです。20261026版の With AI 部門ルールには、このテンプレートが以前想定していた AI 対話ログの一律の提出義務は記載されていません。開催時点のルールや大会固有の要件に従って記録を管理してください。公開前には、生成入力、解答出力、実験結果、認証情報、個人情報、公式配布物の扱いを確認します。

AI を用いた方針の選択や検証の経緯を公開したい場合は、`docs/solutions.md`、`docs/decisions.md`、実験記録、Git 履歴を活用できます。対話ログを残す場合も、個人情報と公開条件を確認してください。

Claude Code で使う定型依頼文は [`prompts/README.md`](../prompts/README.md) にあります。テンプレート自体の設計・変更の記録は [`docs/design-history.md`](design-history.md) を参照してください。
